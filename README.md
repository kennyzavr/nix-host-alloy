# Nix Host Alloy 

Infrastructure-as-Code (IaC) фреймворк на базе Nix для декларативного управления личной инфраструктурой.

Инструмент предназначен для энтузиастов, гиков и владельцев homelab-ов. Цель проекта — дать возможность собрать весь ваш зоопарк устройств (ноутбуки, домашние ПК, VPS, виртуалки и серверы) в единую связную инфраструктуру. 

Фреймворк использует собственную модульную систему (работающую на уровень выше стандартных модулей NixOS). Это решает проблему того, как переиспользовать значения между хостами. Вы описываете конфигурацию кластера целиком, при этом сохраняя возможность гибко настраивать каждый хост индивидуально.

## Основные модули системы

* **Умный менеджмент секретов и фактов**
  Работает поверх `agenix`. Работа модуля базируется на том, что у вас есть мастер-ключи, которыми шифруются глобальные мастер-секреты, затем фреймворк автоматически перешифровывает их под ключи конкретных хостов. 
  Также есть «факты» (открытые значения в репозитории) и генераторы для автоматического создания фактов и секретов. Для удобного управления всем этим используется CLI на Python.

* **Overlay-сети из коробки (WireGuard + GRE + Babeld)**
  Готовый модуль для объединения хостов в одну сеть. Использует WireGuard для поднятия p2p-каналов за единым интерфейсом. Поверх них через GRE создаются отдельные интерфейсы для каждого канала и для того чтобы гонять ip пакеты поверх wg (wireguard выстает только как L2 уровень), babeld берет на себя динамическую маршрутизацию. В общем случае не заточен под конкретную топологию, можно строить wg каналы в любом варианте.

* **Jails (systemd-nspawn) как first-class citizens**
  Фреймворк позволяет настривать контейнеры как полноценных участников инфраструктуры. Они работают в overlay-сетях наравне с обычными хостами. Это позволяет разворачивать софт изолированно в рамках одного NixOS-конфига, избавляя от возможных конфликтов между софтом разных сервисов на одном хосте.

* **Управление TLS и внутренний mTLS**
  Фреймворк разделяет работу с классическими сертификатами и защиту внутренних коммуникаций:
  * **Модуль `tls`** отвечает за выпуск и обслуживание сертификатов (в том числе публичных) для хостов и jails. Сертификаты всегда выпускаются на уровне хоста, а затем безопасно раздаются локальным сервисам-потребителям или прокидываются напрямую внутрь контейнеров через монтирование дерикторий.
  * **Модуль `mtls`** предназначен для шифрования трафика внутри кластера и взаимной аутентификации сервисов, генерирует статические сертификаты. Это решает проблему безопасности в overlay сетях: overlay-сеть в общем случае не обязана быть full-mesh, из-за динамического роутинга трафик между двумя сервисами может идти через транзитные узлы кластера.

* **DNS абстракции (зоны и записи)**
  Alloy предоставляет удобную абстракцию над DNS-зонами и отдельными записями. Это позволяет любым другим модулям или сервисам декларативно добавлять нужные им статические DNS-записи в общую конфигурацию.

## Интегрированные сервисы

В проекте есть набор готовых модулей-оберток над популярным софтом. Они глубоко интегрированы с базовыми фичами фреймворка (секретами, сетью, сертификатами):

* **`http-edge`** — простой HTTP-шлюз на базе Nginx.
* **`dns-edge`** — DNS-шлюз на базе dnsdist.
* **`tls-edge`** — TCP-прокси (HAProxy) с терминацией публичного TLS.
* **`dns-auth`** — легковесный authoritative DNS для отдачи статических зон.
* **`dns-acme`** — сервис для обслуживания ACME DNS-01 челленджей. Работает через CNAME-делегирование: обычные DNS-сервера остаются глупыми и отдают статику, а этот сервис по `dnsupdate` обслуживает запросы клиентов.
* **`smtp-edge`** — SMTP-релей (Postfix + Rspamd).
* **`postbox`** — сборка Postfix + Dovecot2 для поднятия своей почты.
* **`ca`** — свой Certificate Authority на базе `step-ca`.
* **`xhttp-proxy`** — обертка над Xray (настройка XHTTP inbound). Умеет автоматически генерировать конфиги для клиентов, раздавать их по HTTP или сохранять в секреты. Клиентскую часть можно развернуть на любом хосте кластера парой строк без ручной настройки конфигов.

- [ ] Пофиксить баги с работой `qemu-vm` на ветке `nixos-unstable`.
- [ ] Полноценно прикрутить декларативную настройку дисков с помощью `disko`.

- [ ] Полноценный запуск виртуалок со всем вышеперечисленным (файловые системы на disko, bootloader, initrd, SSH для расшифровки на старте).
